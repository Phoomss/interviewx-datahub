## 1. บทสรุปสำหรับผู้บริหาร (Executive Summary)

บันทึกการเปลี่ยนแปลงฉบับนี้จัดทำขึ้นเพื่อบันทึกผลการทบทวน การปรับปรุงแก้ไข และการปรับประสานความสอดคล้องอย่างรอบด้านภายใต้ **ระยะที่ 1 — การปรับประสานข้อกำหนดระบบ (Phase 1: Requirement Alignment)** ของแพลตฟอร์ม InterviewX

วัตถุประสงค์หลักของระยะที่ 1 คือการสร้างข้อกำหนดระบบซอฟต์แวร์ที่มีความชัดเจน รัดกุม สอดคล้องกันทุกส่วน และพร้อมนำไปสู่การพัฒนาจริง (Implementation-ready) โดยกำหนดขอบเขตและแยกความแตกต่างระหว่าง 2 ส่วนติดต่อผู้ใช้ (Frontend) อย่างเป็นรูปธรรม:
1. **เว็บแอปพลิเคชันแบบตอบสนอง (Responsive Web Application):** รองรับการใช้งานผ่านเดสก์ท็อป แท็บเล็ต และเว็บเบราว์เซอร์บนมือถือ ครอบคลุมผู้ใช้งานทุกบทบาทความปลอดภัยในระบบ (Guest, Registered User, Researcher, Payment / Finance Admin, System Admin)
2. **แอปพลิเคชันบนอุปกรณ์เคลื่อนที่แบบเนทีฟ (Native Mobile Application):** แอปพลิเคชันแยกติดตั้งเฉพาะบนระบบปฏิบัติการ Apple iOS และ Google Android ออกแบบเฉพาะสำหรับกลุ่มผู้ใช้งานทั่วไป (End Users: Guest และ Registered User) ภายใต้สิทธิประโยชน์ตามระดับแพ็กเกจสมาชิก Free, Basic และ Pro

ทั้งสองแพลตฟอร์มถูกออกแบบให้แยกขาดจากระบบบริหารจัดการหลังบ้าน โดยสื่อสารกับ **สถาปัตยกรรมบริการหลังบ้านร่วมกัน (Shared Backend Architecture)** ผ่าน REST API ที่ผ่านการตรวจสอบสิทธิ์ความปลอดภัยอย่างเข้มงวด

## 3. การแบ่งแยกขอบเขตแพลตฟอร์มและสถาปัตยกรรมระบบ (Platform Scope & Architecture)

### 3.1 ขอบเขตของเว็บแอปพลิเคชัน (Web Application Scope)
- **เทคโนโลยีพัฒนา:** Next.js ร่วมกับ TypeScript และ Tailwind CSS
- **ขนาดหน้าจอที่รองรับ:** ออกแบบ Responsive Layout ครอบคลุม Desktop (≥1024px), Tablet (768px–1023px) และ Mobile Browser (360px–767px)
- **บทบาทผู้ใช้งานที่รองรับ:**
  - `Guest (ผู้เยี่ยมชม):` ค้นหาข้อมูล หน้าหลัก แนะนำระบบ และทดลองทำข้อสอบตัวอย่าง
  - `Registered User (ผู้ใช้ทั่วไป):` ฝึกจำลองสัมภาษณ์ (ข้อความและเสียง) รับผลประเมิน ดูประวัติ และจัดการโปรไฟล์
  - `Researcher (ผู้วิจัย):` สืบค้นและส่งออกชุดข้อมูลวิจัยแบบ Differential Privacy ตามการกำกับดูแล (รอบ R3)
  - `Payment / Finance Admin (ผู้ดูแลการเงิน):` ตรวจสอบบัญชีรายได้ ตรวจสอบคำขอคืนเงิน และจัดการแคตตาล็อกแพ็กเกจ (รอบ R3)
  - `System Admin (ผู้ดูแลระบบ):` บริหารจัดการคลังคำถาม ปรับแต่งพรอมต์และเกณฑ์รูบริก AI และตรวจสอบ Audit Logs ถาวร
- **ขอบเขตการบริหารจัดการ:** งานบริหารระบบ การเงิน และงานวิจัยทั้งหมด สงวนไว้ให้เข้าถึงได้เฉพาะบน Web Application เท่านั้น

### 3.2 ขอบเขตของแอปพลิเคชันมือถือเนทีฟ (Native Mobile Application Scope)
- **เทคโนโลยีพัฒนา:** แอปพลิเคชันติดตั้งแยกต่างหากสำหรับ iOS และ Android (ข้อเสนอแนะ: React Native / Expo ตามการตัดสินใจ D-M02)
- **กลุ่มเป้าหมายผู้ใช้งาน:** กลุ่มผู้ใช้งานทั่วไปเท่านั้น (`Guest` และ `Registered User`)
- **ระดับแพ็กเกจสมาชิกที่รองรับ:** Free, Basic และ Pro (ควบคุมโควตาผ่านระบบหลังบ้าน)
- **ขอบเขตทางสถาปัตยกรรม:** ถือเป็นส่วนติดต่อผู้ใช้แยกเฉพาะอย่างชัดเจน ไม่ใช่ Responsive Web หรือ PWA และตัดขาดจากฟังก์ชันผู้ดูแลระบบ การเงิน และงานวิจัยโดยสิ้นเชิง

### 3.3 สถาปัตยกรรมบริการหลังบ้านร่วมกัน (Shared Backend Architecture)
- ทั้ง Web และ Native Mobile เชื่อมต่อไปยังบริการหลังบ้านคลัสเตอร์เดียวกัน:
  - **NestJS Modular Monolith:** จัดการตรรกะทางธุรกิจหลัก, ตรวจสอบสิทธิ์ (Authentication), ควบคุมการเข้าถึง (RBAC), บริหารเซสชัน, ตรวจสอบโควตาแพ็กเกจ และส่งต่อเหตุการณ์ผ่าน Outbox
  - **FastAPI AI Service:** บริการประมวลผลโมเดล AI แบบสเตตเลส (Stateless) สำหรับประเมินคำตอบตามเกณฑ์รูบริกและวิเคราะห์การพูด
  - **ฐานข้อมูล PostgreSQL:** แหล่งความจริงหลักเพียงแหล่งเดียว (Single Source of Truth) สำหรับจัดเก็บข้อมูลเชิงสัมพันธ์
  - **Redis / BullMQ:** คิวประมวลผลงานประเมินผลแบบอะซิงโครนัสและป้องกันการประมวลผลซ้ำ
  - **พื้นที่จัดเก็บอ็อบเจกต์ (MinIO / S3):** จัดเก็บไฟล์เสียงสัมภาษณ์ชั่วคราวพร้อมการเข้ารหัส
- **กฎเกณฑ์ทางสถาปัตยกรรม:** ห้ามสร้างฐานข้อมูลแยกซ้ำซ้อน และห้ามเขียนตรรกะทางธุรกิจซ้ำซ้อนระหว่าง Web และ Mobile โดยการสื่อสารทั้งหมดกระทำผ่าน REST API พร้อมการเข้ารหัส TLS 1.3

## 4. รายละเอียดการปรับปรุงเอกสารแต่ละฉบับ (Detailed Modifications)

### 4.1 การปรับปรุงเอกสารข้อกำหนดระบบ (SRS)
- **ข้อมูลส่วนหัวและการกำกับดูแล:** ปรับปรุงเวอร์ชันเป็น `1.1 DRAFT`, วันที่อ้างอิง `13 พฤศจิกายน 2026` และเพิ่มประกาศการปรับประสานขอบเขต
- **หมวดที่ 1 (บทนำและการกำกับดูแล):** เพิ่มคำจำกัดความครอบคลุมทั้ง Web Application และ Native Mobile Application พร้อมนิยามศัพท์ HIG, IAP, APNs, FCM, Keystore, Keychain และ Platform Scope
- **หมวดที่ 2 (หลักฐานและผู้มีส่วนได้ส่วนเสีย):** นำเสนอข้อมูลผลสำรวจความต้องการใช้งานจริง (82.4% ต้องการใช้งานทั้งบนคอมพิวเตอร์และมือถือ) และจัดวางแผนงานให้ R1 เปิดตัวบน Responsive Web ก่อนขยายสู่ Native Mobile ในรอบ R2
- **หมวดที่ 3 (ขอบเขต ข้อสมมติ และแผนงาน):** ปรับปรุงตารางขอบเขตโดยเพิ่มคอลัมน์จำแนก Web Application และ Native Mobile Application พร้อมระบุข้อสมมติทางเทคนิค 5 ประการสำหรับการพัฒนาบนมือถือ
- **หมวดที่ 4 (บริบทระบบและกรณีการใช้งาน):** ปรับปรุงตารางกรณีการใช้งาน UC01–UC10 โดยระบุแพลตฟอร์มที่รองรับอย่างชัดเจน
- **หมวดที่ 5 (ข้อกำหนดเชิงหน้าที่):** คงรหัสข้อกำหนดเดิมทั้ง 40 รายการ (FR01–FR36) พร้อมระบุแท็ก `[ แพลตฟอร์ม: ... ]` กำกับทุกข้อ และปรับปรุง **FR15** อย่างสมบูรณ์พร้อมกำหนดเกณฑ์การยอมรับ 7 ข้อที่วัดผลได้
- **หมวดที่ 6 (ข้อกำหนดที่ไม่ใช่เชิงหน้าที่):** ปรับปรุง **NFR08** ให้ครอบคลุมทั้ง WCAG 2.2 AA (เว็บ), เทคโนโลยีสิ่งอำนวยความสะดวกบนมือถือ (HIG / TalkBack) และการซิงก์ข้อมูล 100% พร้อมบันทึกข้อกำหนดความปลอดภัยบนมือถือใน NFR01, NFR04, NFR09 และ NFR19
- **หมวดที่ 7 (การกำหนดสิทธิ์และการควบคุม):** เพิ่มคำอธิบายความแตกต่างระหว่าง Role, Subscription Tier และ Platform Scope พร้อมจัดทำ **ตารางการเข้าถึงแพลตฟอร์ม (Role × Platform)**, **ตารางสิทธิ์ตามแพ็กเกจ (Tier × Platform)** และ **กฎเกณฑ์การควบคุมสิทธิ์ 7 ประการ**
- **หมวดที่ 8 (เลเยอร์ AI และการประเมินผล):** ระบุชัดเจนว่าโมเดลประเมินผลทำงานบน Cloud Server เท่านั้น ไม่มีการรัน On-device LLM บนมือถือในรอบ R1 และ R2
- **หมวดที่ 9 (สถาปัตยกรรมและเทคโนโลยี):** ปรับปรุงสแตกเทคโนโลยีส่วนหน้าให้ครอบคลุม Next.js และ React Native
- **หมวดที่ 10 (การคุ้มครองข้อมูลและความเป็นส่วนตัว):** เพิ่มข้อกำหนดการล้างแคชไฟล์เสียงบนมือถือภายใน 24 ชม. และขั้นตอนขอลบบัญชีในแอปมือถือตามกฎระเบียบของ App Store
- **หมวดที่ 11 (แผนการส่งมอบและ Roadmap):** กำหนดให้ Native Mobile เปิดตัวในรอบ R2 ควบคู่กับระบบสัมภาษณ์ด้วยเสียง
- **หมวดที่ 12 (ภาคผนวกคำศัพท์):** บันทึกคำศัพท์เฉพาะด้านโมบายล์
- **หมวดที่ 13 (เมทริกซ์การตรวจสอบย้อนกลับ):** สรุปการเชื่อมโยงข้อกำหนดทั้ง 64 รายการ
- **หมวดที่ 14 (ทะเบียนการตัดสินใจ):** บันทึกประเด็นการตัดสินใจ D-M01 ถึง D-M11

| มิติการเปรียบเทียบ | ข้อกำหนดเดิมใน Baseline v1.0 | ข้อกำหนดฉบับปรับปรุงใน v1.1 DRAFT |
|---|---|---|
| **ชื่อข้อกำหนด** | FR15 ใช้งานได้หลายอุปกรณ์ | FR15 การเข้าถึงข้ามแพลตฟอร์มและความสอดคล้องของระบบ (Multi-Platform Access & Consistency) |
| **คำอธิบายขอบเขต** | รองรับ Desktop, Tablet, Mobile Responsive Web | ระบุชัดเจนถึงการแยกเป็น 2 ส่วนติดต่อผู้ใช้: Responsive Web Application และ Native Mobile Application (iOS / Android) |

| **การตรวจสอบสิทธิ์** | ระบุการล็อกอินทั่วไป | ใช้ระบบบัญชีและ JWT ร่วมกัน มีระบบสลับอุปกรณ์ที่ราบรื่น |
| **การประสานข้อมูล** | ไม่ได้ระบุรายละเอียดการซิงก์ข้อมูล | กำหนดการซิงก์ข้อมูลข้ามแพลตฟอร์ม 100% สำหรับข้อมูลโปรไฟล์ เซสชัน ประวัติ โควตา และความยินยอม |
| **เกณฑ์การยอมรับ (AC)** | ไม่มีเกณฑ์การวัดผลที่ชัดเจน | กำหนดเกณฑ์การยอมรับ 7 ข้อที่วัดผลได้และทดสอบได้จริง พร้อมระบุเป็นข้อเสนอรอการอนุมัติ |

### 5.2 การเปรียบเทียบ NFR08 — การเข้าถึงได้อย่างเท่าเทียมและความสอดคล้อง
| มิติการเปรียบเทียบ | ข้อกำหนดเดิมใน Baseline v1.0 | ข้อกำหนดฉบับปรับปรุงใน v1.1 DRAFT |
|---|---|---|
| **ชื่อข้อกำหนด** | NFR08 การเข้าถึงได้ (Accessibility) | NFR08 การเข้าถึงได้อย่างเท่าเทียมและความสอดคล้องข้ามแพลตฟอร์ม (Cross-Platform Accessibility & Consistency) |
| **เป้าหมายมาตรฐาน** | WCAG 2.1 AA | ขยายเป็น WCAG 2.2 AA สำหรับ Web และ Apple Human Interface Guidelines / Android Accessibility Suite สำหรับ Mobile |
| **สิ่งอำนวยความสะดวก** | รองรับการอ่านหน้าจอทั่วไป | รองรับ Dynamic Type / Scale text และระบบอ่านหน้าจอ VoiceOver (iOS) และ TalkBack (Android) |
| **ความถูกต้องของข้อมูล** | ไม่ได้ระบุ | รับประกันความสอดคล้องของข้อมูลบัญชี ประวัติ และโควตาระหว่าง Web และ Mobile แบบ 100% |

## 6. สรุปขอบเขตโมดูลของ Native Mobile Application

### 6.1 โมดูลที่อยู่ในขอบเขต (In-Scope Modules — 17 โมดูล)
1. การตรวจสอบสิทธิ์ (Authentication)
2. การเข้าถึงสำหรับผู้เยี่ยมชม (Guest Access)
3. การลงทะเบียนและเข้าสู่ระบบ (Registration & Login)
4. การเริ่มต้นใช้งานระบบ (Onboarding)
5. โปรไฟล์ผู้ใช้งาน (User Profile)
6. การตั้งค่าการสัมภาษณ์ (Interview Setup)
7. ห้องจำลองการสัมภาษณ์ (Interview Room)
8. การสัมภาษณ์แบบข้อความ (Text-based Interview)
9. การสัมภาษณ์แบบเสียง (Voice-based Interview)
10. การประเมินผลโดย AI (AI Evaluation)
11. ผลการประเมินและข้อเสนอแนะ (Evaluation Results & Feedback)
12. แดชบอร์ดสรุปผล (Dashboard)
13. ประวัติการสัมภาษณ์ (Interview History)
14. ข้อมูลแพ็กเกจสมาชิก (Subscription Information)
15. การจัดการความยินยอมและความเป็นส่วนตัว (Consent & Privacy)
16. การจัดการบัญชีผู้ใช้ (Account Management)
17. การเชื่อมโยงและประสานข้อมูลข้ามแพลตฟอร์ม (Cross-Platform Data Synchronization)

### 6.2 โมดูลที่อยู่นอกขอบเขต (Out-of-Scope Modules — 7 โมดูล)
1. คอนโซลผู้ดูแลระบบ (Admin Console)
2. พอร์ทัลผู้วิจัย (Researcher Portal)
3. การบริหารจัดการผู้ใช้งาน (User Administration)
4. การบริหารจัดการโมเดล AI (AI Model Administration)
5. การบริหารการเงินและการชำระเงิน (Payment / Finance Administration)
6. รายงานรายได้และการเงิน (Revenue & Financial Reports)
7. การจัดการชุดข้อมูลงานวิจัย (Research Data Management)

### 6.3 ประเด็นที่อยู่ระหว่างรอการตัดสินใจ (Pending Decision Modules — 6 ประเด็น)
1. การแจ้งเตือนแบบพุช (Push Notifications: APNs / FCM) — เชื่อมโยง D-M05
2. การยืนยันตัวตนด้วยไบโอเมตริกซ์ (Biometric Authentication) — เชื่อมโยง D-M06
3. การเชื่อมโยงเชิงลึก (Deep Linking & Universal Links) — เชื่อมโยง D-M07
4. การบันทึกเสียงเบื้องหลัง (Background Audio Recording) — รอการออกแบบระบบเสียง
5. โหมดการสัมภาษณ์แบบออฟไลน์เต็มรูปแบบ (Full Offline Mode) — เชื่อมโยง D-M08
6. การประมวลผล AI บนเครื่องอุปกรณ์ (On-device AI Processing) — เชื่อมโยง D-M08

## 8. สรุปความพร้อมและขั้นตอนถัดไป (Next Steps & Implementation Readiness)

1. **การนำเสนอและขอมติอนุมัติ:** นำเสนอเอกสารชุด `v1.1 DRAFT` แก่คณะกรรมการผู้มีส่วนได้ส่วนเสีย (Product Owner, Architecture Review Board, Security & Legal) เพื่อพิจารณาอนุมัติปรับสถานะเป็น `v1.1 Approved Baseline`
2. **การตัดสินใจประเด็น D-M01 ถึง D-M11:** จัดประชุมเชิงปฏิบัติการเพื่อลงมติข้อสรุปในประเด็นทางสถาปัตยกรรมและการเงินทั้ง 11 ข้อ
3. **การเข้าสู่ระยะที่ 2 (Phase 2 — Technical Specifications & API Contracts):** จัดทำ OpenAPI Specifications, Zod Schemas และข้อกำหนดการประสานงานระหว่าง NestJS และแอปพลิเคชันมือถือ
4. **การเตรียมสภาพแวดล้อมทดสอบ:** ตั้งค่าสภาพแวดล้อมการจำลองและชุดทดสอบอัตโนมัติ (Automated E2E / Accessibility Test Suites) สำหรับทั้ง Web และ Mobile
